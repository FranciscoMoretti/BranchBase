# Give managed resources independent owners and stable named instances

Managed resources use the existing selectable-instance machinery under a registered resource identity, independent of their consumers' project configuration fingerprints. A machine-wide registry points to an authoritative definition file and execution directory, allowing several projects to share an instance without copying its commands. Profiles bind to a resource ID and instance name; recipe revisions require separate approval and never choose a new volume identity implicitly.

The initial owner strategy is an explicit durable directory plus a content-hashed source-file manifest, rather than copying entire repositories into snapshots. Direct local command files must appear in that manifest; authors must include transitive scripts, Compose files, and build inputs too. Stop retains the captured identity and rejects changed owner recipes or source files, requiring restoration of the captured revision. This favors preserving data over guessing how a changed script might stop an old stack. Idle policy belongs to the owner definition. Lifecycle operations serialize across the daemon's projects, and persisted runs protect shared resources until their consumers stop.

Local input files are read at execution time; only their descriptors are retained. Resolved connection bindings override local inputs. Commands using local input files do not capture stdout/stderr in persisted logs, avoiding accidental credential disclosure. Public outputs must not contain secrets. This supersedes ADR 0006's restriction that cross-project resources must be externally managed.
