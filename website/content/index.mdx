Manage their worktrees, services, and resource usage from one place with BranchBase.

Give each checkout its own application endpoints, share infrastructure when it makes sense, and select a separate instance when a branch needs different data. Use the dashboard or CLI to keep track of what is running as your agents work in parallel.

## Choose connections independently

| Application checkout | Infrastructure selection | Why |
| --- | --- | --- |
| Main | Shared instance `0` | Normal development |
| UI changes | Shared instance `0` | Reuse the same services |
| Schema changes | Separate instance `1` | Work with different database state |
| Integration checks | Separate instance `1` | Exercise that same schema |

A profile records these choices. Application ports and infrastructure identity stay independent. Stopping one application preserves infrastructure that another active consumer still uses.

## Start with observation

You can add a project before creating configuration. BranchBase discovers Git worktrees and observes local listeners and resource use. To launch commands, add `.branchbase.json`, review the commands, and approve their fingerprint.

BranchBase is **macOS-first** and uses **Bun**. Codex integration is optional. Docker is required only when your repository's infrastructure commands use it.
